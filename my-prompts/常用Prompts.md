# 我常用的三条 Prompt

> 这是我自己的提示词库，按场景分类。每条都记录"输入 → 处理 → 输出 → 效果对比"。

## 1. JD 拆解与匹配度打分

**用途**：投递前判断"这个岗位我值不值得投、缺什么"。

```text
你是 AI 产品方向的招聘官。下面是我的简历要点和一条岗位 JD。
请输出：
1) 该岗位真正在考核的 3 项核心能力（按重要度排序，并引用 JD 原文）
2) 我的经历逐条对应情况：命中 / 部分命中 / 缺失
3) 若我缺失某项，用我现有经历中最接近的一条做"平移证明"（不要编造经历）
4) 我应该在第 1 段自我介绍里先说的那句话（30 字内）

【我的简历要点】
...
【岗位 JD】
...
```

**效果对比**：第一版只说"你适合这个岗位"，没告诉我该先说什么；加上第 4 点后，我每次面试都能直接开口。

## 2. JD 批量打标（配合项目使用）

**用途**：把采集到的 JD 转成结构化表格。

```text
你是数据标注员。请严格按我给出的字段和标签口径，处理下面的岗位 JD。

【字段】id / company / title / location / level / days_per_week / duration / salary / skills_hard / skills_soft / is_entry / evidence
【标签口径】见仓库 docs/labeling-spec.md，共 20 类，同义词必须归并
【规则】
1. 只抽取 JD 中明确出现或明确隐含的要求，不得凭岗位名称臆测
2. 每条判断必须在 evidence 给出 JD 原文依据；没有依据的标签不输出
3. 输出 Markdown 表格，按公司名字母序排列
 
【JD 原文】
...
```

**质量校验**：每次跑完随机抽 20 条自己复核，一致率低于 90% 就回来改口径。

## 3. 评测标准设计（面试高频题练习器）

**用途**：练"如果让你设计一个评测方案，你怎么做"这道必考题。

```text
我要为一个 AI 客服产品设计评测方案。请按下述结构输出，且每部分都必须给出具体可执行的例子，不要只讲概念：
1) 评测目标（对应哪个业务指标）
2) 评测维度拆解（互斥且穷尽）
3) 每个维度的样本设计：正常样本 / 边界样本 / 对抗样本各 2 条
4) 评分口径（几分制、判分规则、多人打分时如何校验一致性）
5) 试跑方案（多少条样本、多久迭代一次）
6) 这套方案的失效场景是什么
```
