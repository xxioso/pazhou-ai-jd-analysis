# 打标口径说明（Labeling Spec）

这份文件的目的：**让任何一个人拿到我的数据，都能复现出和我一样的标签。**
面试官会问"你的标签怎么定的"——答案就在这份文件里。

## 一、表格字段定义

| 字段 | 类型 | 说明 | 示例 |
|---|---|---|---|
| id | 整数 | 采集顺序编号 | 001 |
| company | 文本 | 公司名 | 某科技有限公司 |
| title | 文本 | 岗位名称原文 | AI产品实习生 |
| location | 文本 | 工作地点，精确到地铁站或园区 | 广州·琶洲 |
| level | 枚举 | 学历要求 | 本科 / 硕士 / 不限 |
| days_per_week | 整数 | 每周要求到岗天数 | 4 |
| duration | 文本 | 实习时长要求 | 3个月以上 |
| salary | 文本 | 薪资原文 | 150-200元/天 |
| skills_hard | 多值 | 硬技能，用 `/` 分隔 | Python / SQL |
| skills_soft | 多值 | 软技能，用 `/` 分隔 | 沟通 / 抗压 |
| is_entry | 枚举 | 是否明确接受零经验/不限背景 | 是 / 否 / 未说明 |
| evidence | 文本 | 支撑上述判断的 JD 原文片段 | "熟悉SQL优先" |
| raw_text | 文本 | JD 原文（可截取要求部分） | — |

## 三、打标规则

1. 只抽取 JD 中**明确出现或明确隐含**的要求，不凭岗位名称臆测。
2. 每条判断必须在 `evidence` 给出 JD 原文依据；找不到依据的标签不输出。
3. 同义词按上表归并。
4. 批量处理时按公司名字母序排列，避免遗漏。

### `is_entry` 字段的判定标准（v2，2026-10-08 修订）

| 取值 | 判定标准 |
|---|---|
| 是 | JD 明确写了"不限专业""不限学历"或"欢迎零经验/应届"，**或专业范围明确包含本人专业（经济/数字经济）** |
| 否 | JD 明确要求相关专业、相关经验 |
| 未说明 | JD 既没排除也没欢迎 |

**修订记录**：v1 只写"是否明确接受零经验"，导致"接受经济学背景"和"接受零经验"被混为一谈。
定标依据：第 003 条 JD 明确写"计算机、信息管理、人工智能、**经济**或相关专业优先"，据此判定为"是"；
第 001、002 条未提及经济类专业，判定为"未说明"。

## 四、质量校验（每次打标都要做）

- 每条记录至少有 1 个 `skills_hard` 或 `skills_soft`，否则标记"待人工复核"。
- `evidence` 为空的行占比超过 10% 时，停止输出并检查输入质量。
- 随机抽 20 条人工复核，标签一致率低于 90% 时说明口径需要进一步收敛。
